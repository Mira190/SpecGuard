# Haiku fast-tier reduced review: on vs off (holdout 2, 2026-10-20)

**Question.** Does the "fast-tier" reduced review change outcomes? A model whose name marks it as fast (`src/engine-model.js` tier table) makes `src/post.js` `reducedReasons` push `tier`. In a reduced review, only high-confidence findings with at least 2 verified citations go inline; the rest become summary one-liners.

**Setup.** Offline and $0. Harness: [`tier-arm.js`](tier-arm.js).
- **Arms:**
  - **A** is the complete mock-replay context of every holdout-2 run, saved in `SpecGuard-evidence/out/r<run>/run0-A/`.
  - **B** is a copy of the same context with `engine-model.json` `tier` rewritten to `normal`.
- **Code and runs:** both arms ran the same `post.js` (main 5cb518d), serially.
- **Corpus:** bug runs 39120706885, 39120718089 and 39120729276; clean runs 39120712567, 39120723905 and 39120735452.
- **Excluded:** 1 run is unusable in both arms (`pydantic-ai-hclean2-2`, run 39120735452). The publisher rejected it: "requirements must be an array".
- **Checks:**
  - B's reduced reasons equal A's minus `tier` in 287 of 287 runs (0 violations). Reasons come from the summary's "Reasons:" line.
  - A's inline output equals the saved raw `result.json` in all 287 runs.

| | Bug runs | Clean runs |
|---|---|---|
| Runs scored | 135 | 152 |
| A reduced | 135 | 152 |
| Reduced only by `tier` | 122 | 143 |
| Non-tier reason (all `degraded`; cannot move) | 13 | 9 |
| Findings moved summary → inline (A → B) | 31 | 3 |
| Findings moved inline → summary | 0 | 0 |
| Inline comments per run, A: median / p90 / max | 0 / 1 / 3 | 0 / 0 / 2 |
| Inline comments per run, B: median / p90 / max | 0 / 2 / 4 | 0 / 0 / 2 |
| Status flips | 0 | 0 |

- **Moved findings:** the 31 findings moved on bug runs, by blind-h2 label: real direct 0, real indirect 0, miss 29, ungraded 2.
- **Delivered-direct catches (blind-h2 grade `direct`, delivered inline):** 5 in A and 5 in B, the same five items.
  - This matches [testgap-evidence-2026-10-20.md](testgap-evidence-2026-10-20.md).
  - 3 direct items have no recorded finding index, so they are outside both counts.

**Decision: keep the tier reason.**
- **The rule passed.** The pre-stated rule was "delete iff direct catches don't fall and clean-PR median inline ≤2". It passed: 5 → 5 catches, and the clean-PR median is 0.
- **The reviewer (specguard-e0) overrode it.** The rule left out bug-PR precision, and 29 of the 31 findings that the gate holds back on bug runs were graded miss (0 real).
- **The gate works as a precision filter.** Removing it adds about 31 inline misses per 135 bug runs and recovers no catch.
