## 5. Practical notes

- **Re-running Kite without changing files**: a plain re-run is skipped (the head already has a summary) and Kite's workflow has no `force` input. Add an empty commit (same tree) to each `exp/*` branch through the API: `gh api repos/Mira190/Kite/git/commits -f message=... -f tree=<tree> -f "parents[]=<sha>"`, then `PATCH git/refs/heads/exp/<b>`. Keep `#` out of the message: it is read as an issue reference. The scan: `gh workflow run specguard-audit.yml -R Mira190/Kite`. Cost: about $0.005 per PR review and $0.5 per scan (Haiku).
- The 10 `exp/*` branches carry several such empty commits now.
- The dogfood job reviews every SpecGuard PR; it found two real test-side problems today (a skipped-test fixture inside a test body, the 400-character replacement line). Read its summary before merging.
- Tooling gotcha: shell heredocs through the agent's bash lose one level of backslashes. Edit JS with escapes through a file editor or a script written to disk, not through `python -c`/heredoc string literals.
- Untracked local files (`docs/review*.md`, `docs/research.md`, `docs/SpecGuard_critical_shift_left_audit_2026-10-14.md`, `docs/concise-skill/`) are the owner's notes; they were deliberately not committed (public repository).
